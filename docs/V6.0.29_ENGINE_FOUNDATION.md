# HexCore V6.0.29 — Modular environment engine foundation

This build preserves the uploaded V6.0.28 site's existing rendered worlds and interactions. It does NOT claim the exterior has been remade or a new interior has been connected.

## Integrated now
- `src/engine/runtime.js`: installed by `main.js` after its WebGL renderer is created; tracks FPS approximation, frame duration, draw calls, triangle count. Read-only diagnostics: `window.hexcoreEngine.stats()`.
- `src/engine/asset-pipeline.js`: Promise-cached texture and glTF/GLB loading using Three.js `GLTFLoader`; optional DRACO and KTX2 decoding support. Configure decoder/transcoder asset paths for compressed models; they are not yet bundled in this version.
- `src/engine/materials.js`: reusable HexCore-style physically based and emissive materials.
- `src/engine/effects.js`: GLSL shader-based portal surface and rising/falling animated code particle fields.
- `src/engine/scene-system.js`: registry for distinct environments with cleanup and a pocket-dimension scene factory. Registered future scenes are intentionally not activated, so the existing rooms and exterior are preserved.
- `src/engine/physics.js`: lazy Rapier WebAssembly integration, loaded ONLY when called. No physics applied to existing game mechanics.

## APIs for the interior rebuild
```js
import {createPocketDimension} from './engine/scene-system.js';
const engine=window.hexcoreEngine;
engine.worlds.register('demo-dimension', () => createPocketDimension({title:'HEXCORE'}));
// Do not enter a new world while the existing world is visible unless intentionally switching.
// engine.worlds.enter('demo-dimension');
console.log(engine.stats());
```

## Testing limitations
Static JavaScript syntax and archive integrity were checked. Runtime rendering has not yet been verified in the user's browser, and new effects are not active by default. The website currently imports Three.js through its existing CDN. External GLTF loader addon URLs use the same pinned Three.js version. Rapier is a lazy CDN dependency and requires internet access for first load. DRACO and KTX2 decoders must be deployed before compressed assets are used.
